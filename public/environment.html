voicebox — projects and folders

A project's files live in one of three places: the browser's own storage for this site, a folder you pick, or a folder on this machine. This page always says which one, and says who can change the files there. The same project name in a different browser is a different project — nothing here tries to match them up.

Start a project

What setup does: a project is a folder plus the environment that holds it. The turns that read and save files run in the Voicebox server, so that server needs a folder it can name before it can do anything.

Why it is needed: with no project, reads and writes are refused — there is nowhere for them to go. This browser's own storage needs no path and no host token, but turns cannot write into it yet; a folder you pick is the same, read-only for turns. A folder on this machine is the one turns can write into, and it is where the files stay openable in your own editor.

The order

  1. Start Voicebox on the machine whose files you want to use — that server is what saves them.
  2. Create a project and choose where its files live: this browser's storage, a folder you pick, or a folder on this machine.
  3. If you chose a folder on this machine, the loop writes there and turns save into it. The other two are held by this page; turns cannot write there yet.

Where should the files live?

Kept in this browser's own storage (origin storage, OPFS) — not a folder on your disk, and it asks for no host token and no path. A name you have used before opens that project instead of making a new one. Turns cannot write here yet; this page lists, reads and writes these files.

How this page talks to those environments

The browser environment is a worker inside this page — it answers over a message channel, no network. The local server is an HTTP API on this machine (loopback): the page asks, the server acts inside its own root and answers with what it observed or a named refusal. A remote environment is the same API on another machine, reached through a paired credential — the page never holds the remote's key. The one rule across all three: a decision never crosses the wire — an answer carries observed facts or a named refusal, never a grant.
